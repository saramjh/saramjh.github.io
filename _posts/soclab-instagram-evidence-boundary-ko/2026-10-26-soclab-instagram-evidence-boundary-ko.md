> **English edition:** [What Instagram Comments Can and Cannot Tell Us About a Relationship](/soclab-instagram-evidence-boundary-en/)

인스타그램 댓글과 답글을 정리하는 소랩 파일럿 기록을 다시 살펴봤다. 허가받은 전문 계정 한 곳에서는 어떤 게시물에서 댓글이 달렸고 어떤 답글이 이어졌는지 출처를 남길 수 있었다. 하지만 그 사람이 전에 보낸 DM 전체나 실제로 협업을 확정했는지는 이 기록에서 알 수 없었다. 확인된 대화와 빈칸을 같은 사실처럼 보이게 해서는 안 되겠다고 생각했다.

**이번에 확인한 것:** 접근 가능한 댓글과 답글은 출처가 있는 접점의 시작이다. 과거 DM 전체, 실제 계약, 상대의 감정이나 구매 의향을 증명하지는 못한다.

이 기록을 바탕으로 만들고 싶은 것은 사람을 점과 선으로 잇는 그래프보다, 관측된 대화와 운영자가 적은 메모와 아직 모르는 내용을 나란히 확인하는 작업 공간이다. 다시 연락하기 전에 무엇을 확인해야 하는지 사용자가 직접 판단할 수 있어야 한다.

다만 이번 글은 로컬 시제품에서 확인한 자료의 범위를 정리한 기록이다. 실제로 구현된 부분과 앞으로 만들어야 하는 기능을 구분해서 적는다.

## 실제로 확인한 범위: 한 개 계정의 댓글·답글

2026년 10월 25~26일 개발 문서에 남긴 로컬 파일럿에서는 **명시적으로 승인된 Instagram Professional 계정 한 개**를 대상으로 공식 권한으로 접근 가능한 댓글 및 소유자의 답글을 관측했습니다. 관측된 이벤트를 관계별로 묶고, 원문에 연결된 근거를 남기며, 사람별 초기 요약을 만드는 기능을 검증했습니다.

확인된 내용은 다음 범위에 한정됩니다.

- **관측된 상호작용:** 접근 권한이 있는 게시물의 댓글·답글 등 실제 API 기록
- **관계 맥락의 시작점:** 관련 이벤트의 처음·마지막 시점, 확인된 교환 내용, 출처 링크
- **결정론적 요약:** 관측된 기록과 명확한 규칙에 근거한 초기 Contact 360 요약
- **운영자 작성 메모:** 필요할 때 관리자가 기록한 사실을 API 관측과 **별도 출처**로 저장

운영자 메모에 '협업 논의 중'이라는 내용이 있어도, Instagram API가 협업을 인증한 것은 아닙니다. 메모는 **운영자의 기록**이며, 출처를 섞으면 해석의 신뢰가 무너집니다.

이 검증은 로컬 시제품의 기능 근거이지, 모든 Instagram 사용자가 당장 가입해서 이용할 수 있는 SaaS라는 뜻이 아닙니다.

## 무엇을 알 수 없는가

댓글 하나를 보고 상대가 브랜드를 좋아한다거나 구매할 준비가 됐다고 결론 내릴 수는 없습니다. 댓글과 답글만으로는 아래와 같은 맥락이 빠질 수 있습니다.

| 궁금한 정보 | 댓글·답글 기록만으로 가능한 판단 |
| :--- | :--- |
| 최근에 실제로 질문하거나 답했는가 | 접근 가능한 기록이 있으면 확인 가능 |
| 그 사람과 이전에 주고받은 모든 DM | **확인 불가** — 별도 메시징 권한 및 구현이 필요 |
| 협업 조건이 최종 확정됐는가 | **확인 불가** — 별도 근거가 있어야 함 |
| 상대가 현재 구매 의사가 있는가 | **추정 금지** — 명시적인 사실 없이는 알 수 없음 |
| 지난 방문 이후 어떤 정보가 바뀌었는가 | 완전한 수집·기준 시점 비교가 구현·검증돼야 가능 |

이 표의 목적은 기능이 부족하다는 사실을 감추는 것이 아닙니다. **사용자가 믿을 수 있는 단서가 어디까지인지**를 드러내는 것입니다. 보이지 않는 데이터를 그럴듯한 관계 점수로 메우는 것은 좋은 사용자 경험이 아닙니다.

## 다음 연락을 준비하는 사람에게 필요한 화면

가상의 사례를 하나 들어보겠습니다. 운영자가 예전에 문의했던 상대에게 다시 연락하려고 합니다. 상대의 이름만 제시하면 운영자는 SNS 앱으로 돌아가 과거 기록을 반복해서 찾아야 합니다.

그 대신 관계 화면이 다음 질문에 답하는 편이 낫습니다.

1. **마지막으로 확인된 접점은 무엇인가?** 출처와 관측 시점을 함께 보여줍니다.
2. **이전에 어떤 주제를 다뤘는가?** 실제 댓글·답글에 등장한 주제만 표시합니다.
3. **누가 추가 정보를 기록했는가?** 운영자 메모인지 API 관측인지 명확히 구분합니다.
4. **무엇이 아직 미확인인가?** 메시지 전체, 협업 확정, 최신 의향은 모른다고 표시합니다.
5. **다음 행동은 무엇인가?** 확인이 필요한 항목을 제안하되, 사람의 검토와 적법한 권한을 우선합니다.

이것은 실제 고객의 사례가 아닌 **가상의 업무 흐름**입니다. 또한 다섯 단계가 전부 현재 제품에 구현됐다는 의미도 아닙니다. 현재 구현된 출처 기반 관측·초기 요약을 바탕으로 검증해야 할 사용 경험을 설명한 것입니다.

## 데이터가 쌓이면 자동으로 관계를 이해하게 될까?

반드시 그렇지는 않습니다. 더 많은 수집이 더 좋은 판단을 보장하지도 않습니다. 누락된 기간, 계정 권한, 관측 가능한 항목, 잘못 중복된 이벤트가 구분돼야 합니다.

소랩은 우선 **사실 수집·출처·관측 범위·중복 처리**를 결정론적 코드로 관리하는 방향입니다. 추후 AI가 사용된다면 자료에 근거해 문장을 요약하거나 가능한 후속 질문을 제안하는 **선택적 계층**이어야 합니다. 실제로 확인하지 못한 사실을 채워 넣거나 친밀도·구매 가능성을 단정하는 기능이 돼서는 안 됩니다. 현재 원격 AI API 요약이 이미 상용 제공된다고 주장하지 않습니다.

## 아직 남은 검증과 공개 베타 조건

지금까지의 파일럿은 출처가 있는 댓글·답글 관측과 제한적인 사람별 요약을 입증했습니다. 하지만 일반 고객이 계정 연결만으로 같은 첫 가치를 경험하도록 하려면 여러 단계가 더 필요합니다.

- 일반 고객용 공식 Meta 인증·권한·심사 조건
- 고객별 안전한 데이터 격리, 철회·삭제 및 안정적인 동기화
- 누락·미확인 상태를 오해 없이 보여주는 UX
- 반복 방문에서 실제로 도움이 되는 관계 기억과 다음 행동 검증

따라서 댓글 자동 DM, 과거 메시지 전체 분석, Threads 자동 수집, 범용 공개 베타는 **현재 제공 기능이 아닌 향후 검증 대상**입니다.

## 앞으로 확인하고 싶은 질문

운영자나 크리에이터 입장에서 옛 상대에게 다시 연락해야 할 때, **마지막 댓글·답글의 원문**, **그때 다루던 주제**, **이전에 약속한 다음 일** 가운데 무엇이 가장 먼저 필요할까요?

이 질문에 대한 실제 답변이 모여야 제품의 우선순위를 조정할 수 있습니다. 아직 받은 적 없는 사용자 의견을 꾸며내지 않겠습니다.

Instagram의 계정 유형·권한·댓글 기능을 더 확인하려면 [Meta가 공개한 Instagram API 문서](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api)를 참고할 수 있습니다. API 설명과 별개로, 위 파일럿의 구현 여부는 소랩 개발 측 검증에 근거한 주장입니다.

다른 개발 기록은 [블로그 글 목록](/)에서 탐색할 수 있습니다. 같은 주제의 [English article](/soclab-instagram-evidence-boundary-en/)도 준비했습니다. 관련 후속 글이 실제로 발행되면 이 글과 양방향으로 연결할 예정입니다.
